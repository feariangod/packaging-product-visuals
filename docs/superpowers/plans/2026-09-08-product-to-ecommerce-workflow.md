# Product-to-Ecommerce Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` in this session or `superpowers:executing-plans` in a separate session. Follow the tests-first order and record evidence in the plan workspace.

**Goal:** Replace the mode-first v0.1 interface with a stage-gated product-to-ecommerce workflow while preserving the existing rights, lock, receipt, and QA guarantees.

**Architecture:** Keep `SKILL.md` as a concise router. Move stage-specific guidance into focused references, keep normative schemas in `contracts.md`, and use public YAML fixtures plus pytest assertions to make the workflow inspectable. The optional Python helper remains local and deterministic, but its HTML view becomes a bilingual workflow review surface.

**Tech Stack:** Markdown Agent Skill, YAML/JSON fixtures, Python 3.10-3.14, pytest, Pillow, static HTML/CSS generated by Python.

**Spec:** `docs/specs/2026-09-08-product-to-ecommerce-workflow.md`

## Global Constraints

- Use only fictional public fixtures and owned or documented-redistributable assets.
- Preserve the permission schema, authorization provenance, RFC 6901 overrides, source hashes, QA hashes, independent-review rules, output safety, and bounded statuses.
- Treat research evidence, observations, inference, hypotheses, and unknowns separately.
- Keep `compare` and `refine` as internal operations; replace generic `present` with ecommerce asset roles.
- Do not claim production, regulatory, legal, manufacturing, preference, conversion, or platform approval.
- Do not publish, push, tag, or release until all final gates pass.
